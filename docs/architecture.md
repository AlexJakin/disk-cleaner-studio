# 架构与扩展

```text
QML 界面
   ↓ 属性 / slots / changed 信号
AppController（主线程；配置、选择、任务生命周期）
   ↓ 后台 worker + 取消事件 + 进度信号
ScanRepository / scanner / CleanupService
   ↓
SQLite 扫描索引、固定位置的备份 manifest、WizTree CSV
```

## 约定

- `core` 使用 Python 标准库，不依赖 Qt，便于 CLI、测试与后续迁移。
- 大文件导入、WizTree 扫描、计划计算、备份与恢复都运行在后台线程，Qt 对象只在主线程更新。
- 无法确定完成比例的操作显示阶段、数量和耗时，不编造百分比。
- `summary` 是扫描时的快照，清理后不会偷偷扣减其中数字；需要重新扫描才能形成新的占用数据。
- 候选项只是建议。清理执行器重新按本机允许目录检查资格，不能单靠 CSV 路径和 risk 标签授权删除。
- 计划与备份数据不能作为任意文件访问入口；恢复需要完整性、路径、内容和冲突检查。
- 取消保留已完成的扫描与备份；清理中取消应停止后续删除并报告真实状态。应用忙碌时需要等待取消完成再关闭。

## 关键文件

| 位置 | 职责 |
| --- | --- |
| `app.py` | 应用启动、QML 引擎、命令行选项、离屏验证 |
| `controller.py` | Qt 数据桥、单任务调度、选择与设置 |
| `core/analysis.py` | CSV 流式导入、候选规则、目录与历史查询 |
| `core/scanner.py` | WizTree 发现、参数数组调用、退出码、超时与取消 |
| `core/cleanup.py` | 结构化计划、全量备份验证、受限清理、恢复 |
| `qml/` | 实际桌面视图和交互 |
| `tests/` | CSV 兼容性、任务状态与执行安全回归 |

## 后续方向

可以继续添加扫描列表分页、规则编辑器的只读预览、更多软件缓存适配、局部重新扫描和更细的历史趋势。新增可执行规则必须同时添加路径保护、备份、恢复与失败情形的测试；不要将泛化的“cache”子串作为删除权限。

当前恢复采取保守冲突策略，不覆盖已重新生成的缓存文件。大规模扫描的导入速度、数据库体积和目录页查询应使用真实数据进一步测量。实时变化的缓存仍存在文件系统并发窗口，执行前应关闭对应应用。
